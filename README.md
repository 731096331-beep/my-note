#等保2.0的一些理解


## 先搞清楚等保2.0是什么

等保的全称是"网络安全等级保护"，2.0是相对于2007年那套标准（大家习惯叫1.0）来说的。
核心依据是《网络安全法》第21条，法律层面把等级保护定下来了。
2019年5月发布了三个新标准——GB/T 22239（基本要求）、GB/T 28448（测评要求）、
GB/T 25070（安全设计技术要求），同年12月1日正式实施，2.0时代就是从这开始的。

## 跟1.0比，变化主要在哪

**地位变了，这是最本质的一条。** 1.0的依据是公安部牵头的几个部门规章和国务院
147号令，说到底是行政法规层面。2.0直接挂在《网络安全法》下面，网络安全法第21条
把等级保护制度写进了法律条文。性质从"你应该做"变成了"你必须做"，不做就是违法，
这个分量完全不一样。

**名字换了。** 从"信息安全等级保护"改成"网络安全等级保护"。别小看这几个字，
说明监管的视角从单纯保护"信息"本身，扩大到保护整个"网络"运行安全，对象范围
一下子就宽了。

**保护对象扩了一圈。** 1.0时代管的主要就是传统信息系统，云计算、手机APP、
物联网设备这些东西出来后，老标准根本套不上去，测评机构也很头疼。2.0干脆
针对云、移动互联、物联网、工业控制、大数据分别出了扩展要求。就拿云计算来说，
明确了平台和云上系统分开定级，责任边界划分、测评对象界定都有说法了，
不再是各说各话。

**整体框架重拆了。** 技术要求从1.0的五个层面（物理安全、网络安全、主机安全、
应用安全、数据安全）调整成：安全物理环境、安全通信网络、安全区域边界、
安全计算环境、安全管理中心。我个人的理解是，1.0的分法偏"按设备类型分"，
2.0偏"按安全能力域分"——特别是"安全管理中心"这个层面是新东西，强调对
全网安全设备的集中管控，以前设备各管各的、日志各存各的，现在要求统一
监测、统一审计。

**可信验证是新面孔。** 2.0在几个关键节点（通信、边界、计算环境）都写了
可信验证的要求，方向是往可信计算体系上引。不过说实话，这条目前落地的
程度参差不齐，很多测评现场就是看看有没有相关的机制设计，算是方向性的要求。

**测评结论分级了。** 1.0的结论基本就是符合、基本符合、不符合三档，很粗。
2.0改成了优、良、中、差四档，打分制。"优"的门槛相当高——综合得分90以上
且不能有中高风险项，实务里能拿"优"的系统凤毛麟角，大部分单位的目标
就是保"良"。

**定级流程更严了。** 虽然还是"自主定级"这个原则，但2.0把专家评审、主管
部门核准这些环节做实了，定级报告要备案，公安机关对定级结果有监督。
以前那种"自己拍脑袋定个二级完事"的空间被压缩了不少。

## 基本流程

走的还是定级、备案、建设整改、测评、监督检查这条线：

1. 定级：自己初步定，然后专家评审，主管部门核准，最后去公安机关备案
2. 建设整改：对照相应等级的要求补安全措施
3. 测评：找有资质的测评机构做
4. 三级系统每年至少测评一次，四级每半年一次，二级一般是建议两年一次

等级一共五级，二级和三级是最常见的，四级往上基本就是能源、金融这类关键设施了。
