## 一、实验目的

1. 掌握 Wireshark 抓包软件的基础使用方法，学会网卡选择、捕获过滤器设置、数据包查看与 TCP 流追踪操作。
2. 观察 QQ 传输图片时产生的网络数据包特征，区分业务流量与 DNS、ICMP、心跳包等无关网络报文。
3. 尝试捕获 QQ 通信数据包，分析能否从网络载荷中提取 QQ 账号信息，理解新旧 QQ 通信协议的差异。
4. 理解 TLS 传输加密原理，对比早期 OICQ 协议，认识传输加密对网络通信隐私的保护机制。
5. 学会识别 TCP 分片报文，掌握通过报文长度、时间戳、目的 IP 等特征判断业务流量的分析思路。

## 二、实验环境

- 硬件：PC 计算机
- 软件：Windows 操作系统、Wireshark 抓包工具、PC 版 QQ 客户端
- 网络环境：有线 / 无线局域网，可正常访问互联网

## 三、实验原理

Wireshark 是一款开源网络数据包捕获与分析工具，可以监听网卡上经过的所有网络报文，解析以太网、IP、TCP、UDP 等多层协议头部信息。

早期旧版 QQ（OICQ 协议）使用 UDP 报文传输，部分用户信息以明文或简单编码传输，抓包后可直接解析得到 QQ 账号。

现代 PC 端 QQ 的消息、图片文件传输均采用 **TLS 加密**，应用层数据在发送前完成加密，网络链路上传输的只有密文。TCP 协议会对较大的数据进行分片传输，一张图片会被拆分为多个 TCP 报文段发送。

TLS 加密的特点：在没有本次会话的密钥情况下，仅捕获网络数据包，无法解密载荷，看不到明文聊天内容、图片二进制数据以及明文账号信息。

实验中还会遇到多种干扰报文：DNS 报文用于域名解析；ICMP 为网络探测报文；QQ 心跳小包周期性发送，用来维持客户端在线；电脑后台软件更新会产生其他大流量数据包，需要根据特征区分过滤。

## 四、实验内容与实验步骤

1. **前期准备**

    打开 Wireshark，查看本机 IP 地址（使用 cmd 命令 `ipconfig`），记录本机 IPv4 地址。关闭电脑多余后台软件，减少无关网络流量干扰。打开 QQ 并登录账号，准备发送图片。

2. **配置捕获过滤器，开始抓包**

    在 Wireshark 捕获过滤器输入：`ip.addr == 本机IP && tcp`，选中本机正在使用的网卡，清空之前捕获的旧数据包，点击开始捕获。

    > 操作顺序：**先开启抓包，再在 QQ 发送图片**，保证完整捕获本次传输流量。

3. **触发 QQ 图片传输**

    在 QQ 聊天窗口，选择一张图片发送给好友，等待图片上传发送完毕。图片发送完成后，点击 Wireshark 停止捕获。

4. **筛选目标数据包**

    观察捕获列表，找到发送图片瞬间集中出现的一组数据包。这类报文特点：报文长度较大，多数接近 1460 字节（TCP 最大分段长度 MSS），短时间内连续批量出现，目的 IP 归属为腾讯服务器。

5. **追踪 TCP 流，分析载荷**

    选中其中一个目标数据包，右键选择 `Follow → TCP Stream`，查看本次 TCP 会话全部上下行数据，观察流内数据内容。

6. **记录现象，区分干扰流量**

    识别实验中的无关报文：DNS 小包、ICMP 探测包、QQ 心跳包、系统后台更新流量，记录区分方法。

7. **整理实验现象，对比理论知识，完成分析。**

## 五、实验结果与分析

本次实验使用 Wireshark 对 PC 端 QQ 发送图片的网络流量进行捕获与分析，实验目的是通过抓取 QQ 通信数据包，尝试从报文载荷中提取 QQ 账号信息，并观察图片传输对应的网络流量特征。

实验操作流程：首先在 Wireshark 中选定本机网卡，设置过滤规则 `ip.addr == 本机IP && tcp`，清空历史捕获数据包，点击开始捕获后，在 QQ 客户端向好友发送一张图片，待图片发送完成后停止抓包。在捕获结果中筛选发送图片瞬间产生的数据包，可以观察到一组连续的 TCP 分片报文，数据包单段长度较大，大量报文接近以太网 MTU 上限 1460 字节，在时间轴上集中爆发，与发送图片的操作时间点高度吻合，初步判定这一组报文为 QQ 图片传输产生的流量。

选中其中一个数据包，右键选择追踪 TCP 流，查看该会话完整通信载荷。可以发现流内全部数据均为无意义的乱码二进制密文，无法找到 JPG 图片文件头 `FF D8 FF` 或 PNG 文件标识，也不存在明文形式的 QQ 账号、聊天文字等信息。经分析，新版 QQ 客户端的消息、图片传输均基于 TLS 加密协议，传输载荷全部经过加密处理，抓包只能获取加密后的密文数据。在没有 TLS 会话密钥的前提下，无法直接从捕获的数据包中解密还原原始图片，也无法直接提取明文 QQ 账号。

实验过程中出现了流量干扰问题：本机同时存在 DNS 查询、ICMP、软件后台更新、QQ 心跳包等无关流量。DNS 报文一般长度很小，用于域名解析；ICMP 为网络探测报文，与 QQ 业务无关；QQ 心跳包为周期性小包，用于维持客户端在线状态；后台软件下载流量虽也存在大长度数据包，但服务器 IP 归属不是腾讯服务器，通过核对服务器 IP 归属、报文产生时间，可以区分这类干扰数据包，排除误判。

对比旧版 OICQ 协议相关资料，早期 QQ 采用 UDP 通信，部分信息以明文或简易编码形式传输，可通过抓包直接解析出 QQ 账号。而现代即时通讯软件广泛使用 TLS 传输加密，通信内容不再裸奔在网络中，传统网络嗅探方式无法直接窃取用户身份信息与通信内容。

**实验小结**：本次成功捕获到 QQ 图片传输对应的 TCP 加密分片流量，能够根据报文长度、时间特征、服务器 IP 识别出图片传输的数据包。但受 TLS 加密保护，无法从捕获的数据包中还原图片，也无法直接抓取明文 QQ 账号。该实验直观验证了传输层加密对网络通信隐私的保护作用，单纯依靠 Wireshark 抓包嗅探，已经不能实现对现代加密即时通讯应用的信息窃取。

## 六、思考题

1. 为什么旧版 OICQ 可以抓到 QQ 号，新版 QQ 抓不到明文账号？

    > 答：早期 OICQ 使用 UDP 协议，部分信息明文传输；新版 QQ 使用 TLS 加密，所有应用层载荷加密，网络链路只有密文，无密钥就无法读取明文信息。

2. 图片传输为什么会产生大量连续的 TCP 大包？

    > 答：TCP 存在最大分段大小 MSS，图片数据量大，会被拆分成多个分片依次传输，所以短时间出现大量大包。

3. 什么是 TCP 流追踪功能，在本次实验有什么作用？

    > 答：TCP 流追踪会把同一个 TCP 连接所有上下行报文重组，还原完整会话数据，方便一次性查看整个通信交互内容。

## 七、实验心得

通过本次 Wireshark 抓包实验，我熟悉了网络抓包工具的操作流程，加深对 TCP 分片、TLS 加密、IP 协议等网络理论知识的理解。实验验证了现代互联网传输加密的重要意义，网络嗅探只能捕获链路层和网络层头部信息，加密后的应用数据可以有效保护用户隐私。同时实验也让我意识到网络流量环境复杂，存在大量无关干扰报文，需要结合报文特征、时间、IP 地址综合分析流量，不能仅凭包大小简单判断业务类型。
